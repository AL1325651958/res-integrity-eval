# 技术架构设计

> 版本：V1.0　适用系统：医院个人科研成果诚信综合评价系统　定位：低并发、内网部署、易维护、可申请软著

## 1. 决策总览

| 决策项 | 选择 | 理由 |
|---|---|---|
| 整体形态 | B/S 前后端分离，单体应用 | 医院内网访问，无微服务复杂度，单体足够且易部署运维 |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + Pinia + ECharts | 组件生态成熟、国内资料丰富、类型安全，适配管理后台类系统 |
| 后端 | Java 17 + Spring Boot 3.2.x + MyBatis-Plus | 医院信息科主流 Java 生态；Spring Boot 官方长期维护；MyBatis-Plus 提升 CRUD 效率 |
| JDK 兼容性 | 首选 JDK 17；如内网仅支持 JDK 8，降级 Spring Boot 2.7.18 | 降级仅涉及 `javax`→`jakarta` 包名差异，业务代码基本不变 |
| 数据库 | MySQL 8.0（InnoDB，utf8mb4） | 需求指定；8.0 支持 JSON、窗口函数、CTE，满足规则快照与统计 |
| 认证授权 | Spring Security + JWT 无状态令牌 + RBAC（角色-菜单-按钮） | 五级角色权限隔离；无状态便于内网横向扩展与前后端分离 |
| 定时任务 | Spring `@Scheduled` | 年度评价计算、每日风险筛查、工单催办，量小无需消息队列 |
| 文件存储 | 本地磁盘 + 附件元数据入库 + 鉴权下载 + 可选 AES 加密 | 内网场景，附件量小；不暴露裸 URL，统一走后端鉴权 |
| 报表/导入导出 | Apache POI（EasyExcel）｜OpenPDF | 历史成果 Excel 批量导入；个人档案 PDF 导出 |
| 部署 | 单机 Linux + Nginx + 内嵌 Tomcat jar + MySQL 8.0 | 低并发（在线 ≤ 50），单机性价比最高；提供 Docker Compose 可选方案 |
| 并发指标 | 在线并发 ≤ 50，注册用户 ≤ 500，日活 ≤ 200 | 医院单院区规模，按最低档设计，预留扩展 |

## 3. 前端设计

### 3.1 技术栈

- Vue 3（组合式 API）+ TypeScript
- 构建：Vite 5
- 状态：Pinia（user 用户信息、permission 动态路由）
- 路由：Vue Router 4，**登录后按角色动态注册路由**（菜单来自后端）
- UI：Element Plus；图表：ECharts（看板折线/柱状/饼图）
- 请求：Axios 统一封装（拦截器注入 Token、统一响应体 `{code,msg,data}`、401 跳登录）
- 规范：ESLint + Prettier + husky

### 3.2 工程结构

```
frontend/
├─ src/
│  ├─ api/            # 按模块封装接口（auth/achievement/integrity/risk/system/dashboard）
│  ├─ assets/         # 静态资源
│  ├─ components/     # 通用组件（UploadFile、ScoreTable、StatusTag…）
│  ├─ layout/         # 主布局（侧边菜单 + 顶栏 + 标签页）
│  ├─ router/         # 路由与动态路由守卫
│  ├─ store/          # Pinia stores
│  ├─ utils/          # request.js、auth.js、format.js
│  └─ views/
│     ├─ dashboard/   # 个人/科室/全院看板
│     ├─ achievement/ # 成果填报、我的成果、审核列表
│     ├─ integrity/   # 诚信档案、年度评分明细、申诉
│     ├─ risk/        # 风险预警、核查工单、黑名单
│     ├─ system/      # 用户/科室/角色/菜单/字典/规则/日志
│     └─ profile/     # 个人信息、修改密码
└─ vite.config.ts
```

### 3.3 权限控制

- **动态路由**：登录后按用户角色返回菜单树，前端注册可访问路由；
- **按钮级权限**：`v-permission` 指令按 `perms` 标识（如 `integrity:check:handle`）控制操作按钮显隐；
- 五级角色：普通医护人员（个人端）、科室管理员、科研科审核员、科研诚信委员会、院领导，另设系统管理员（运维）。

## 4. 后端设计

### 4.1 技术栈

- Java 17 + Spring Boot 3.2.x（spring-boot-starter-web/security/validation）
- MyBatis-Plus 3.5.x（内置分页、逻辑删除）
- JWT：`jjwt`；密码：BCrypt
- POI/EasyExcel（导入导出）、OpenPDF（档案 PDF 导出）
- Lombok、MapStruct（可选）、Hutool（工具）
- 构建：Maven；包名 `com.hospital.integrity`

### 4.2 工程结构

```
backend/
├─ pom.xml
└─ src/main/
   ├─ java/com/hospital/integrity/
   │  ├─ controller/    # REST 控制器
   │  ├─ service/       # 业务层（含评价引擎、风控筛查引擎）
   │  ├─ mapper/        # MyBatis-Plus Mapper
   │  ├─ entity/        # 实体（对应 26 张表）
   │  ├─ dto/ vo/       # 请求/响应模型
   │  ├─ security/      # JWT 过滤器、登录、权限注解
   │  ├─ config/        # 全局配置（跨域、MyBatisPlus、Jackson、线程池）
   │  ├─ task/          # 定时任务（年度评价、风险筛查、催办）
   │  ├─ util/          # 文件、加密、Excel、PDF 工具
   │  └─ exception/     # 全局异常与统一响应
   └─ resources/
      ├─ mapper/*.xml
      ├─ application.yml
      └─ sql/（初始化脚本引用）
```

### 4.3 接口规范

- RESTful：`/api/v1/{模块}/{资源}`，如 `/api/v1/achievement`、`/api/v1/risk/check`
- 统一响应体：`{ "code": 0, "msg": "ok", "data": ... }`（code=0 成功，非 0 业务错误）
- 分页参数：`pageNum/pageSize`，返回 `{ total, list }`
- 鉴权：`Authorization: Bearer <token>`，JWT 有效期 8 小时 + 刷新令牌；登录失败 5 次锁定 30 分钟
- 幂等/防重复提交：关键写接口（成果提交、扣分生效）加防重（Redis 可选，无 Redis 时用数据库唯一约束兜底）

### 4.4 定时任务（@Scheduled）

| 任务 | 频率 | 说明 |
|---|---|---|
| 年度评价计算 | 每年 1 月 5 日 | 按上年度生效规则版本计算全员业绩分/扣分/等级，写快照 |
| 风险自动筛查 | 每日 02:00 + 成果入库实时触发 | 一稿多投/署名异常/时间逻辑/黑名单期刊/重复申报 |
| 工单催办 | 每日 09:00 | 超期未认领/未处置工单通知负责人 |
| 公示到期处理 | 每日 08:00 | 公示到期自动归档 |
| 整改到期提醒 | 每日 09:00 | B/C 级整改到期前 3 天提醒 |

## 5. 文件存储与附件安全

- 目录：`/data/integrity/files/{bizType}/{yyyyMM}/{uuid}.{ext}`，文件名 UUID，原始名入库；
- 附件元数据存 `research_attachment`（MD5 去重）；
- **下载统一走 `/api/v1/file/download?id=`，校验登录与数据权限**，Nginx 不直接映射文件目录；
- 敏感附件（身份证、立项书等）可选 AES-128 加密落盘，下载时解密；
- 备份：文件目录随每日增量备份；上传限制单文件 ≤ 20MB，类型白名单（pdf/jpg/png/doc/docx/xlsx/zip）。

## 6. 部署设计（低并发单机）

| 项 | 方案 |
|---|---|
| 服务器 | 应用 + 数据库同机：4C8G（最低 2C4G），Linux（Ubuntu 22.04 / CentOS 7.9） |
| 应用 | `java -jar integrity-system.jar`，systemd 守护，开机自启 |
| 反向代理 | Nginx：前端静态资源 + `/api` 转发 + gzip |
| 数据库 | MySQL 8.0 单实例，`integrity_db`，utf8mb4 |
| 备份 | `mysqldump` 每日 02:00 全量 + binlog 增量（保留 30 天）；附件目录 rsync 每日增量 |
| 发布 | 构建产物 + `schema.sql` 变更脚本（Flyway 可选），先备份后发布，支持回滚 |
| 可选 | Docker Compose（mysql + app + nginx 三容器）一键部署 |

## 7. 非功能性指标（低并发档）

| 指标 | 目标 |
|---|---|
| 在线并发 | ≤ 50 |
| 注册用户 / 日活 | ≤ 500 / ≤ 200 |
| 数据量 | 总行数 ≤ 50 万，年增量 ≤ 2 万 |
| 页面响应 | P95 ≤ 2s；报表/档案导出 ≤ 30s |
| 可用性 | 99.5%（非核心系统）；RPO ≤ 24h，RTO ≤ 4h |
| 安全 | 密码 BCrypt、JWT、五级权限隔离、操作日志留痕不可删、敏感字段脱敏展示（手机号/身份证）、附件鉴权下载 |
| 合规 | 审计日志保留 ≥ 3 年；满足医院内网等级保护二级要求；符合《个人信息保护法》告知同意与最小必要原则 |

## 8. 技术风险与应对

| 风险 | 应对 |
|---|---|
| 内网仅支持 JDK 8 | 降级 Spring Boot 2.7.18，仅 `jakarta` 包名差异，代码评审时统一注意 |
| 无外网依赖（Maven 仓库不可达） | 提前离线打包依赖（`mvn dependency:go-offline`），或内网私服 Nexus |
| 附件增长 | 单文件 ≤ 20MB + MD5 去重 + 年度归档清理策略 |
| 评分规则争议 | 规则全部入库可配置、带版本，历史评价走快照，改规则不影响历史结果 |
| 人员抵触 | 申诉复核机制 + 公示脱敏 + 整改减免，制度配套宣传 |
