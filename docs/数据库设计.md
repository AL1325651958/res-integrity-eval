# 数据库设计

> 版本：V1.0　数据库：MySQL 8.0（InnoDB / utf8mb4）　完整 DDL 见 `sql/schema.sql`，字典与规则初始化见 `sql/init_dict.sql`、`sql/init_rules.sql`

## 1. 设计规范

| 项 | 约定 |
|---|---|
| 主键 | 所有表统一 `BIGINT AUTO_INCREMENT`，主键名 `xxx_id` |
| 字符集 | utf8mb4 / utf8mb4_general_ci（支持中文与 emoji） |
| 时间 | 统一 `DATETIME`，默认 `CURRENT_TIMESTAMP`，更新时 `ON UPDATE CURRENT_TIMESTAMP` |
| 金额/分值 | 统一 `DECIMAL`，分值 `DECIMAL(10,2)`，金额 `DECIMAL(12,2)` |
| 状态 | 一律 `TINYINT` 或短字符串枚举（枚举值见第 4 节状态机与字典） |
| 外键 | **不建物理 FOREIGN KEY**，采用逻辑外键（应用层校验），避免初始化顺序与级联复杂度 |
| 删除 | 用户等基础数据用 `del_flag` 逻辑删除；日志、评价快照、审核流水**物理不删除** |
| 命名 | 表 `业务前缀_名称`（`sys_*` 系统、`research_*` 业务）；字段小写下划线 |

## 3. E-R 关系总览（逻辑关系）

```
sys_dept 1─n sys_user n─n sys_role n─n sys_menu（角色菜单权限）
sys_user 1─n research_achievement（成果）
research_achievement 1─n research_attachment / research_audit_log

research_integrity 1─n research_integrity_detail（明细快照，关联 ach_id / violation_id）
research_rule 1─n research_rule_coeff（系数可全局通用：rule_id 为空）
research_rule（DEDUCT）─n research_violation（违规记录，关联成果、工单）

research_check / research_integrity 1─n research_publicity（公示，biz_ids JSON）

```

## 4. 状态机定义

### 4.1 成果审核状态（research_achievement.status）

```
0 草稿 ──提交──▶ 1 待科室初审 ──科室通过──▶ 2 待科研科终审 ──终审通过──▶ 3 已入库（计分）
   ▲                    │                        │
   │                    ▼                        ▼
   └────────── 4 已退回（科室/科研科退回，可多次）─┘
5 已撤销（本人撤回）/ 6 已作废（事后发现造假，回收计分）
```
- 状态流转均写入 `research_audit_log`，退回必须填意见；
- 已入库成果发现造假 → 作废（6）→ 计分回收 → 触发评价重算。

### 4.2 核查工单状态（research_check.status）

```
PENDING 待认领 ──认领──▶ PROCESSING 核查中 ──取证调查──▶ TO_CONFIRM 待认定
   │                                                       │
   │ 误报撤销                                               ▼
   ▼                                                   CONFIRMED 已认定（生成违规记录）
DISMISSED 误报撤销                                     │
                                                       ▼
                                                  TO_PUBLIC 待公示 ──公示──▶ PUBLISHED 已生效（扣分入账）
                                                                               │
                                                                               ▼
                                                                          ARCHIVED 已归档
```
- 认定生效后可发起申诉（`research_appeal`），复核变更时回写工单结论并重新入账。

### 4.3 违规记录状态（research_violation.status）

```
CONFIRMED 已认定 ──生效──▶ EFFECTIVE 已生效（扣分入账，D级一票否决生效）
                              │
                              ├──（B/C 级）─▶ REFORMING 整改中 ──验收通过──▶ REFORMED 整改完成（扣分减免）
                              └──（D 级）冻结申报资格，不减免
REVOKED 已撤销（复核变更撤销）
```

### 4.4 申诉状态（research_appeal.status）

```
PENDING 待受理 ──受理──▶ REVIEWING 复核中 ──┬─▶ SUSTAINED 维持原判
                                           ├─▶ OVERTURNED 变更裁定（回写扣分/等级）
                                           └─▶ REJECTED 驳回（材料不符）
```

### 4.5 公示状态（research_publicity.status）

```
PUBLISHING 公示中 ──到期自动──▶ FINISHED 已结束（归档）
        └──撤销──▶ CANCELED 已撤销
```

## 5. 索引与约束要点

| 位置 | 设计 |
|---|---|
| 用户 | `emp_no`、`username` 唯一索引；逻辑删除 `del_flag` |
| 成果 | `(user_id, ach_no)` 唯一约束（同一人同一 DOI/专利号/项目号只计一次，防重复申报）；`title(191)` 前缀索引支撑相似度筛查；`ach_type/status/publish_time` 组合查询索引 |
| 评价 | `(user_id, year, period_type)` 唯一，保证一年一评；明细按 `integrity_id`、`ach_id` 索引 |
| 规则 | `rule_no` 唯一；`(rule_type, ach_type)` 查询索引；`(version, effective_date)` 支持版本生效解析 |
| 工单/申诉/风险 | `check_no`、`appeal_no` 唯一；`status`、`user_id` 高频过滤索引 |
| 审计 | `sys_log` 按 `create_time` 索引，支持年度归档 |

## 6. 关键设计说明

1. **分数可追溯**：`research_integrity` 只存汇总，`research_integrity_detail` 逐条存"哪条成果按哪个规则（版本）计了多少分"，配合 `snapshot` JSON 保存当时配置，回答"这 85 分怎么来的"；
2. **规则版本化**：`research_rule` 修改即新版本（`version`+`effective_date`），评价按年度内有效版本计算；历史评价不重算旧版本；
3. **工单与申诉分离**：`research_check` 只承载核查主流程，多轮取证/会签走 `research_check_record`，多轮申诉走 `research_appeal`，避免单表职责过载；
4. **附件通用**：`research_attachment` 以 `biz_type+biz_id` 挂接成果、工单、申诉三类业务，支持 MD5 去重与可选加密；
5. **规则配置 JSON**：`config_json` 存 ROLE_MAP 分档分值（如课题负责人/核心/参与）与 MONEY 金额制参数，避免为每种组合建表；
6. **逻辑外键**：不建物理 FK，由应用层 + 唯一约束兜底，便于批量导入与历史数据初始化。

## 7. 年度评价计算数据流

```
每年1月定时任务（或手动触发重算）
  → 取该年度 [1-1, 12-31] 入库成果（status=3，未作废）
  → 按年度内有效规则版本逐条计分（PERF 规则 + 系数）
  → 汇总业绩总分 perf_score
  → 汇总该年度生效违规扣分（research_violation status=EFFECTIVE/REFORMED，扣除减免）
  → 得有效扣分 deduct_score、最终得分 total_score
  → 查 research_level_config 判定 A/B/C/D（含一票否决）
  → 写 research_integrity（汇总）+ research_integrity_detail（快照）
  → 可发起公示 → 公示期内可申诉 → 公示结束归档
```

## 8. 初始化与备份

- 初始化顺序：`schema.sql` → `init_dict.sql` → `init_rules.sql` → 用户/科室/角色初始数据（`init_admin.sql`，编码阶段提供）；
- 备份：`mysqldump` 每日 02:00 全量 + binlog 增量，保留 30 天；恢复演练每季度一次；
- 归档：`sys_log` 与评价快照按年度归档，审计日志保留 ≥ 3 年。
