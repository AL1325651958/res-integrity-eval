# 部署运维手册

> 适用：医院内网服务器（低并发：在线 ≤ 50、注册用户 ≤ 500）
> 前提结论：**git clone 只拿到源码，不能直接运行**。服务器需安装 JDK 17、Maven、MySQL 8.0、Node.js、Nginx，按本手册构建部署后才可运行。

## 1. 服务器环境要求

| 组件 | 版本 | 用途 |
|---|---|---|
| 操作系统 | Linux（Ubuntu 22.04 / CentOS 7.9+）或 Windows Server | 运行环境 |
| JDK | 17（若内网仅有 JDK 8，后端改用 Spring Boot 2.7 分支，见第 8 节） | 后端运行 |
| Maven | 3.6+ | 后端构建 |
| MySQL | 8.0 | 数据库 |
| Node.js | 18+（建议 20 LTS） | 前端构建 |
| Nginx | 1.20+ | 静态托管 + 反向代理 |
| Git | 任意 | 拉取代码 |

推荐配置：4C8G 起步（最低 2C4G），磁盘 100G+（附件与备份）。

### 1.1 环境安装命令速查

**Ubuntu 22.04 / 24.04**

```bash
sudo apt update
sudo apt install -y git openjdk-17-jdk maven mysql-server nginx curl

# Node.js 20（NodeSource 官方源）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# 启动 MySQL 并设置 root 密码（注意：此密码就是后面 DB_PASSWORD 要填的）
sudo systemctl enable --now mysql
sudo mysql -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '你的强密码'; FLUSH PRIVILEGES;"
# （推荐）或创建专用账号，避免用 root
sudo mysql -e "CREATE USER IF NOT EXISTS 'integrity'@'localhost' IDENTIFIED BY '你的强密码'; GRANT ALL ON integrity_db.* TO 'integrity'@'localhost'; FLUSH PRIVILEGES;"
```

**CentOS 7/8/9（dnf/yum，以 el9 为例）**

```bash
sudo dnf install -y git java-17-openjdk-devel maven nginx
# MySQL 8.0 官方仓库（CentOS 自带的 MariaDB 与 MySQL 8 有差异，请勿混用）
sudo dnf install -y https://dev.mysql.com/get/mysql80-community-release-el9-5.noarch.rpm
sudo dnf install -y mysql-community-server
sudo systemctl enable --now mysqld
# 首次安装的临时密码在日志中，用其执行 mysql_secure_installation 设置正式密码
sudo grep 'temporary password' /var/log/mysqld.log
sudo mysql_secure_installation
# Node.js 20（NodeSource 官方源）
curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash -
sudo dnf install -y nodejs
```

**安装后验证**

```bash
java -version    # 应为 openjdk 17.x
mvn -version     # Apache Maven 3.6+
mysql --version  # 应为 8.0.x
node -v          # 应为 v18 及以上
nginx -v
```

**数据库密码连通性自测**（在跑部署脚本前必做）

```bash
mysql -u root -p'你的强密码' -e "SELECT 1;"
# 若用专用账号：mysql -u integrity -p'你的强密码' -e "SELECT 1;"
# 返回 1 即表示密码正确可用；否则后端启动会报连接失败
```

## 2. 获取代码

```bash
git clone <仓库地址> /opt/integrity
cd /opt/integrity
```

## 3. 初始化数据库

```bash
mysql -u root -p < sql/schema.sql        # 建库建表（integrity_db，utf8mb4）
mysql -u root -p integrity_db < sql/init_dict.sql
mysql -u root -p integrity_db < sql/init_rules.sql
```

- 建库账号建议单独创建业务账号：`CREATE USER 'integrity'@'%' IDENTIFIED BY '强密码'; GRANT ALL ON integrity_db.* TO 'integrity'@'%';`
- 管理员/角色/菜单**无需手工插入**：后端首次启动自动初始化（见第 4 节）。

## 4. 后端构建与部署

```bash
cd /opt/integrity/backend

# 构建（首次会下载依赖，耗时较长；内网无外网需先离线打包依赖，见第 8 节）
mvn clean package -DskipTests
# 产物：target/integrity-system.jar
```

配置（环境变量覆盖 `application.yml` 默认值）：

| 环境变量 | 说明 | 示例 |
|---|---|---|
| `DB_PASSWORD` | MySQL 密码（必配） | `DB_PASSWORD=xxxxx` |
| `JWT_SECRET` | JWT 密钥（≥32 字符，必改） | 随机长字符串 |
| `FILE_PATH` | 附件存储目录 | `/data/integrity/files` |

以 systemd 守护运行（CentOS/Ubuntu）：

```ini
# /etc/systemd/system/integrity.service
[Unit]
Description=Integrity Evaluation System
After=network.target mysql.service

[Service]
Type=simple
User=integrity
WorkingDirectory=/opt/integrity/backend
ExecStart=/usr/bin/java -jar /opt/integrity/backend/target/integrity-system.jar
Environment=DB_PASSWORD=xxxxx
Environment=JWT_SECRET=please-change-to-long-random-secret
Environment=FILE_PATH=/data/integrity/files
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now integrity
journalctl -u integrity -f      # 查看启动日志
```

启动成功后会自动：创建 admin 账号（密码 `admin123`）、6 类角色、菜单与角色-菜单。验证接口：

```bash
curl http://127.0.0.1:8080/api/v1/auth/login -X POST -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
# 期望返回 {"code":0,...,"data":{"token":"...","user":{...}}}
```

## 5. 前端构建与 Nginx 部署

```bash
cd /opt/integrity/frontend
npm install --registry=https://registry.npmmirror.com   # 国内镜像加速
npm run build                                            # 产物：dist/
```

Nginx 配置（`/etc/nginx/conf.d/integrity.conf`）：

```nginx
server {
    listen 80;
    server_name _;

    root /opt/integrity/frontend/dist;
    index index.html;

    # 后端接口反向代理（后端 context-path=/api，前端请求 /api/v1/...）
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 60m;          # 附件上传限制
    }

    # 附件下载/档案PDF等流式接口
    location /api/file/download {
        proxy_pass http://127.0.0.1:8080;
        proxy_buffering off;
    }

    # SPA 前端路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

```bash
nginx -t && systemctl reload nginx
```

浏览器访问 `http://<服务器IP>/`，登录 `admin / admin123`。

## 6. 验证清单

- [ ] `curl /api/v1/auth/login` 返回 code=0
- [ ] 浏览器登录成功进入个人工作台（无 404）
- [ ] 新增一条成果 → 提交 → 科室初审 → 终审入库（自动计分）
- [ ] 附件上传/下载正常（Nginx `client_max_body_size` 已调大）
- [ ] 日志目录有输出、`sys_log` 表有审计记录

## 7. 备份策略（建议）

```bash
# 每日 02:00 数据库全量备份，保留 30 天（crontab）
0 2 * * * mysqldump -uintegrity -p'密码' integrity_db | gzip > /data/backup/integrity_$(date +\%F).sql.gz
find /data/backup -name 'integrity_*.sql.gz' -mtime +30 -delete

# 附件目录每日增量备份（rsync 到备份机/磁盘）
0 3 * * * rsync -av /data/integrity/files/ /data/backup/files/
```

## 8. 常见问题

| 问题 | 处理 |
|---|---|
| 内网无法访问 Maven 中央仓库 | 在有外网的机器执行 `mvn dependency:go-offline` 后整体拷贝 `~/.m2` 到内网，或用内网 Nexus |
| 内网仅 JDK 8 | 后端改依赖 Spring Boot 2.7.18（仅 `jakarta`→`javax` 包名差异），重新 `mvn package` |
| npm 安装慢/失败 | 使用 `--registry=https://registry.npmmirror.com` |
| 登录报"账号或密码错误" | 确认输入 admin/admin123；首次启动自动建号，若曾手动建号会跳过 |
| 页面 404 | 检查 Nginx `try_files` 是否配置（SPA 回退）；浏览器强刷 Ctrl+F5 |
| 附件上传 413 | 调大 Nginx `client_max_body_size` 与后端 `spring.servlet.multipart.max-file-size` |
| 时间显示相差 8 小时 | 检查 `application.yml` 的 `spring.jackson.time-zone: GMT+8` 与 JVM 时区 `-Duser.timezone=Asia/Shanghai` |
| 数据库字符集乱码 | 确认建库使用 `utf8mb4`，连接串含 `characterEncoding=utf8` |
